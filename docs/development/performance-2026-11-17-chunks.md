# Chunk encoding — 2026-11-17 KST

This stage reduces work in the existing encoders. It does not add game mechanics,
parallel simulation or a packet cache. The engine remains unfinished. No package,
release, tag or executable artifact is published.

## Bottlenecks and implementation

The Java adapter scanned all 384 vertical blocks for each height column, including
uniform air; scanned every block again for section occupancy; built 4,096 temporary
u64 palette indices per mixed section; and visited every skylight nibble even where
an entire section had the same value. Both edition palettes searched a short vector
for each voxel. These are actual encoder paths used at spawn and resynchronization,
not a newly invented engine subsystem.

- `Section::count` reads existing mutation/decode counts or uniform occupancy.
- `ChunkSnapshot::non_air_heights` skips empty sections, resolves a solid section
  directly and scans only unresolved columns. It returns world Y above the highest
  non-air block, X-fast, with MIN_Y for an empty column. No cached state is added.
- Java packs its existing four-bit palette directly into 256 u64 words on the stack,
  iterating the world's existing X/Z/Y order instead of checked coordinate lookups.
  The former 32 KiB heap index array is removed; allocator counts and compiled stack
  high-water usage were not measured.
- Both edition adapters use a five-entry reverse palette map while retaining
  first-occurrence order. Bedrock still traverses Y/Z/X and uses its original
  nonspanning 32-bit packing and canonical block hashes.
- Java fills fully dark/bright sections or rows in bulk; mixed rows retain the
  original per-column nibble calculation. All 26 light arrays remain present.

World ownership, COW snapshots, revisions, edit validation, queue and byte bounds,
chunk subscriptions, game decisions, storage version 1, SDK v1–v11, compression,
authentication and connection lifecycles are preserved. No dependency or unsafe
code is added. The vertical-only light model is unchanged; this is not a general
light propagation engine.

The frozen 15 wire digests were captured before production edits, from runtime
`da4f19524ceae7e3fdaecbfec8f585505cff7ea2`, with Java 777 and Bedrock 2225.

Rust 1.100.0, release test executable, thin LTO, Linux x86_64 AMD EPYC 9V45,
five visible logical CPUs, four-CPU cgroup quota, 32 GiB memory limit. No concurrent
local builds, game clients or tests ran during either measurement cohort. Shared
host load is uncontrolled. This is a single-thread encoder kernel, not scaling or
multiplayer TPS evidence.

Five repetitions × five prepared immutable fixtures × three actual encoders ×
1,000 encodes = 75 phases / 75,000 encodes per implementation. Flat, empty, solid,
sparse full-height and dense five-kind fixtures include negative chunk positions
and height boundaries. Each phase has 64 warmups, checks every generated byte
against the expected encoding, and checks its output against the frozen SHA-256.
Java full chunks, Java light updates and serialized Bedrock LevelChunk packets are
measured separately. Quantiles time encoding alone; whole-phase wall/CPU also
include exact byte comparisons and buffer drop. Startup, fixture construction,
sorting and digest computation are outside timing. Compression, encryption, sockets,
disk, rendering and game simulation are excluded. Case order is fixed; this is not
an interleaved randomized causal study or a confidence interval.

## Remaining work

Worst-case mixed-height Java light still calculates individual nibbles, mixed
palette encoding still reads each voxel, and full snapshots still allocate/output
full chunks. A bounded revision-aware shared packet cache should only follow
end-to-end contention/byte measurements and explicit invalidation/recovery tests;
it is not implemented here. Encoders remain on the current session task, so
join/resynchronization bursts still warrant event-loop latency measurements.
No parallel speedup is measured: RMT, ownership migration, work stealing, ECS,
simulation LOD and packet-only terrain LOD remain unimplemented. They need actual
simulation/entity workloads before an algorithm can be selected responsibly.
Arbitrary Bedrock animation/Molang/JSON UI fidelity in stock Java remains a
separate missing content capability. None of these are marked complete by this
encoder change. Next: examine large edit resynchronization work and measure
bounded generation/encoding work under concurrent joins without changing game
ordering or silently dropping updates.
