## Implemented — current source toward 0.1.0

- Java main/hotbar quick moves compute destination merges and partial remainders on the shared owner. Changed stacks receive fresh IDs; allocation failure rolls back the entire operation. Cursor/output, selected slot and request history are preserved. Existing inventory/equipment hooks and native peer updates expose only committed changes. Block-pick packet observations now correctly report Gameplay in both adapters instead of Unsupported.

- NetherNet establishment can continue past an outbound UDP permission failure on one candidate while retaining its existing peer-address policy and establishment deadline. Permission loss on the active session path and socket-level receive permission errors remain fatal to that session. Bounded debug output identifies send/receive path errors without game payloads.

- First run creates an authenticated `sculith.toml` with both edition sessions, loopback listeners and periodic region saving. Existing and invalid configurations are preserved; explicit missing paths fail. `check` remains read-only. `run --offline` applies a local-only in-memory authentication override without enabling disabled legacy sessions. No plugin, welcome or content pack is loaded by default. Windows launchers use the same server-owned configuration path.

- Creative block picking resolves the target on the shared owner, checks initialization/build permission, reach, occlusion and inventory rate, reuses existing counts and preserves displaced items when space remains. Java PickItemFromBlock and native BlockPickRequest synchronize the selected slot and counted inventory. Existing inventory/equipment hooks observe committed changes, while duplicate picks do not duplicate semantic events.

- API v12 adds private console command events with explicit player/console source eligibility. Console-only commands are absent from both edition catalogs; player-only registrations retain their previous behavior and wire format. Local operator requests carry no synthetic player ID and can use the existing world API without connected players. A failed worker disables only its own registrations.

- Local operator console: `help`, initialized-player `list`, serial manual `save` and orderly `stop`. Input is bounded to eight queued lines of at most 256 bytes; EOF leaves the server running and `--no-console` opts out. General examples no longer send an automatic welcome; private message delivery is exercised by a test-only fixture. [Console guide](../guides/hosting.md#console).

- World mailbox profiling separates permit admission, queue wait and owner service wall time. Default Off skips profiler clocks/history; opt-in Monitor/Profile retain bounded recent/detailed metadata. Fixed operation names exclude game/account payloads. CLI captures support separate simultaneous plugin reports, new-file output and joined background writers. The existing 32-slot owner mailbox, leases and game decisions are preserved; this does not implement CPU sampling, simulation ticks or RMT. [Operator guide](../guides/world-profiling.md).

- Subscription/private-recipient filtering precedes delivery, and selected workers serialize the shared immutable event without deep payload cloning. Fan-out encodes the body once while preserving independent request IDs; single-recipient events serialize directly. Bounded request/reply storage is reused, and unused dispatches skip IPC entirely. Action order and backpressure are preserved. Initial plugin IPC instrumentation adds Off/Monitor/bounded Profile modes, rolling exact recent quantiles, encoding/wall times, complete-frame bytes and versioned payload-free reports. A real-Rust fanout benchmark and Linux CPU/RSS/PSS driver provide repeatable baselines. This does not implement CPU sampling, a full game profiler or parallel region simulation. [Operator guide](../guides/profiling.md).

- API v11 adds shared text, boolean, dropdown and integer-slider forms. The same owner validates complete typed replies, deadlines, session IDs and step/length bounds before a single private callback. Java uses stock dialog controls and a bounded flat modified-UTF-8 payload; native uses standard custom forms. Simple forms retain API v3 and the shared one-pending-form slot.

- Configured region snapshots now checkpoint changed revisions every 60 seconds by default. One serial blocking writer prevents overlapping saves; final shutdown waits before capturing newer state. A zero interval disables periodic saving; console requests and final saving remain available. Forced restart recovers completed plugin/block checkpoints; foreign/invalid files remain protected. Player persistence and a write-ahead log remain pending.

- API v10 adds owner-serialized world reads and compare-and-set edits of up to 64 blocks. Reads return one consistent region revision without loading chunks; invalid/stale batches make no changes. Per-plugin and owner work quotas bound calls. Private results return only to the submitting plugin. Committed player/plugin edits share the existing Java/native delivery and expose explicit attribution through the new world hook, preserving the older player-only hook.

## Performance

The matching release IPC benchmark (5,000 calls, 128 warmups, five repetitions) reduces 1/32 large-event dispatch wall time from 766.339 to 267.575 ms and host process CPU from 0.76 to 0.12 s. All-32 dispatch changes from 3,141.371 to 2,728.644 ms. Observed aggregate PSS changes by about 0.5%; single-subscriber tail values rise slightly. No game TPS, allocation count, profiler-mode overhead or RMT improvement is inferred. [Conditions, raw hashes, intermediate regression and scope](performance-2026-11-17.md).

The input-form release kernel measures 10,000 four-control open/submit pairs in **1.587368 ms**. Definitions and reply vectors are prepared before the timer; owner validation, request attribution and response construction are included. A synthetic monotonic clock avoids form-rate exhaustion. This excludes rendering, sockets and plugin IPC and is not a server-TPS or optimization comparison.

The periodic-checkpoint candidate retains the existing release storage probe: 1,000 encodes of a 1,193-byte region in **14.810168 ms**, 1,000 validation/decodes in **18.372249 ms** and 20 atomic save/reload operations in **17.357416 ms**. This is a local small-region/filesystem sample, not a full-region, server-TPS or optimization comparison.

The release authority probe measures 10,000 world reads of 64 blocks in **14.273437 ms** and 1,000 atomic 32-block edit batches in **3.767321 ms**. Requests are prepared before the edit timer; typed response construction, validation and commit are included. Reads leave the loaded chunk count unchanged. The synthetic monotonic clock avoids quota exhaustion; sockets, plugin IPC, rendering and persistence are excluded. This is a local kernel sample, not server TPS or a comparison with another engine.

After removing starter items, the release authority benchmark prepares Stone/Dirt/Grass explicitly before timing. One local sample measures 10,000 movement operations **779.723 µs**, 1,000 placement/break pairs **331.649 µs**, 10,000 inventory transfers **2.872583 ms**, and 10,000 plugin give/view/clear cycles **2.825661 ms**. It retains the same kernel assertions and synthetic clock, excluding sockets, rendering and persistence. These are local samples, not a claimed speedup; the replay cache's initially zero capacity is separately asserted.

API-v9 connection observer release microbenchmark (`cargo test -p sculith-server --release connection_observer_benchmark -- --ignored --nocapture`), median of five 10,000-cycle runs: disabled **377.418 µs**, inbound **3.327606 ms**, inbound plus outbound **4.160279 ms**. Each cycle opens/clones/attaches/drops/drains; enabled directions each create one metadata event. This measures local tracing and bounded-ring delivery, excluding sockets, encryption, plugin IPC and game work. The cases perform different work and are not a speedup or TPS comparison.

The release signing-authority reference validates 1,000 warmed fixture RSA-2048
tokens and their P-384 SDP proofs in 547.716 ms on this host. Run
`cargo test --release -p sculith-server --bin sculith benchmark_microsoft_offer_validation -- --ignored --nocapture`.
This includes token/proof decoding and verification, excluding HTTP, TLS, ICE and
gameplay; it is not a player-capacity or TPS result.

A release-mode Java stream sample encrypts **64 MiB** in 64 KiB writes to a sink in a median of three runs of **1.077398616 s (59.40 MiB/s)**. This includes cipher-state copying/buffer allocation and excludes sockets, framing, RSA, HTTP, pack conversion and game simulation; it is not server TPS.

A local release-mode API-v8 observer probe measures a median of five 10,000-cycle runs: disabled open/drop/drain **459.803 µs**; enabled open/one receipt/player attachment/close/drain **2.405614 ms**. The enabled cycle includes metadata allocation and bounded-ring delivery; both exclude sockets and plugin IPC. The different cycle contents are not a speedup comparison or TPS measurement.

## Known Limitations

- New first runs enable authenticated loopback sessions and world saving. Existing discovery configurations remain discovery-only until edited. Remote listeners require explicit bind/media configuration; official-client online gameplay remains unverified.
- Successful real-account sign-in remains unverified. Test-issued online transcripts and actual official-endpoint negative checks pass. Offline identities are restricted to loopback binds.
- Gameplay remains a bounded creative builder with four block items and 36 inventory slots. Main/hotbar quick moves are supported; general containers, drop/drag interactions, armour/offhand, gravity, simulation ticks, survival, combat and crafting are not implemented.
- Region recovery restores completed periodic/final snapshots. Unflushed edits, persistent player state and a write-ahead log remain pending.
- Initialized peer players and counted held items are displayed within loaded chunks; account skins, armour/offhand, general entity simulation and combat remain pending. The Java adapter has official-game evidence for the limited Linux offline scenario; official Windows game rendering and successful real-account sign-in remain unverified. No complete crossplay claim is made.
- Java currently maps only the five core block states, uses a fixed two-chunk view, and supplies direct vertical skylight without lateral light propagation. General containers and packet compression are pending; login encryption, public chat, commands and configured pack delivery are implemented.
- NetherNet supports local compatibility and configured direct-peer media. Required-authentication mode checks Microsoft token signatures/claims and the P-384 fingerprint proof; offline local mode checks fingerprint ownership and expiry only. The inner Bedrock login policy remains separate. Official entry is user-reported; successful real-account entry, Internet/NAT routing, TURN and signaling proxy support remain unverified or unimplemented.
- Both NetherNet channels now reach the validated owner. A real test commits valid unreliable movement and corrects a large tick/teleport attempt over the reliable channel. Official-client movement/rendering still require verification.
- Only a single region owner is implemented; no parallel region tick scheduler, migration, merging or splitting exists yet.
- Plugins expose lifecycle/MOTD, post-commit game hooks, connection and bidirectional packet metadata, public player commands, private messages, choice/input forms, private sounds and static models through trusted executable processes. WASI Component execution, multi-region world access, general entity APIs, inventory removal/arbitrary slot replacement, command permissions, cancellation, region/entity scheduling and isolation limits are not implemented.
- Conversion supports explicit static PNG overrides, bounded single-clip Vorbis sound events and explicit static cuboid models. Configured HTTP/proxy pack delivery and shared simple forms are implemented; rotated/animated models, arbitrary-UI conversion, content IR, Companion and hot reload are pending. Internet routing/TLS proxy deployment remains unverified.
- Latest protocol types expose camera instruction, preset, aim-assist and spline packets, but Sculith has no camera API or scenario tests yet.
- REA CLI/direct stdio MCP is usable. The active chat tool namespace does not refresh automatically, and no official Windows GDK binary is available here for artifact analysis.
