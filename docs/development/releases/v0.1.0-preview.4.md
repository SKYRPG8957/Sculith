# Windows local WebRTC interoperability preview

Preview 3의 신뢰/계속 선택 후 발생한 Door / InitialConnection-83 문제를 조사하며, 독립 WebRTC 클라이언트에서 재현한 두 연결 오류를 수정했습니다.
Windows 네이티브 검사와 독립 WebRTC 검사는 [빌드 43754939284](https://github.com/SKYRPG8957/Sculith/actions/runs/43754939284), 소스 7b0160a에서 통과했습니다.

- 실제 WebRTC의 인터페이스 바인딩에 대응합니다. HTTP 신호는 127.0.0.1 전용이며, UDP 미디어는 운영체제가 확인한 자기 PC의 주소만 송수신 대상으로 허용합니다.
- DTLS 역할과 SCTP 연결 시작 역할을 분리했습니다. 이전에는 암호화 연결이 완료돼도 상대가 시작한 SCTP 연결을 받지 못하는 경우가 있었습니다.
- HTTP 응답 코드와 첫 ICE·DTLS 패킷 수신을 진단 로그로 구분합니다.
- aiortc/OpenSSL을 쓰는 독립 테스트가 두 데이터 채널, 서버 서명과 실제 베드락 네트워크 설정 응답을 확인합니다. 설치한 서버에 Python이나 테스트 도구는 필요 없습니다.

기존 서버를 Ctrl+C로 종료하고 ZIP 전체를 새 폴더에 푼 뒤 diagnose.cmd를 실행하세요.
접속 주소는 127.0.0.1, 포트는 19132입니다. 기존 설정과 월드를 사용할 때는 서버가 꺼진 상태에서 sculith.toml과 world 폴더 전체를 복사하세요. 서명 키는 보존하며 공유하지 마세요.

실제 Minecraft Windows GDK 클라이언트의 접속 성공은 아직 확인되지 않았습니다. 이번 테스트를 공식 게임 입장이나 렌더링 검증으로 간주하지 않습니다.
Java 월드 입장, 일반 인벤토리·생존·멀티플레이 표시와 완전한 팩 호환성은 아직 구현 중입니다.

NetherNet 코어는 고정한 Apache-2.0 원본과 작은 상호운용성 수정을 저장소에 포함합니다. 원본 라이선스와 변경 기록을 보존하며 Sculith의 MIT 라이선스는 유지합니다.

English: Corrects same-machine interface-bound ICE media and separates SCTP initiation from DTLS role negotiation. Adds independent aiortc/OpenSSL verification through real Bedrock network settings. Official Minecraft gameplay remains unverified. Preserve settings and the whole world directory, stop the old process, extract the ZIP and run diagnose.cmd.
