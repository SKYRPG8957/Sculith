# Windows local connection preview

이번 버전은 기존 RakNet 외에 **NetherNet HTTP/WebRTC 연결 경로**를 추가합니다.
HTTP 상태 조회, 서명된 서버 응답, WebRTC 데이터 채널을 기존 베드락 로그인과 같은 월드 소유자에 연결했습니다.
헤드리스 클라이언트의 실제 소켓 테스트에서 두 전송 방식이 같은 블록 변경을 받는 것을 확인했습니다.
Windows 테스트에서 발견한 loopback 소켓의 LAN 후보 접속 시도(`os error 10051`)도 수정했습니다.
Windows 네이티브 테스트·실행 파일·저장/재시작·ZIP 검증은 [빌드 43751492841](https://github.com/SKYRPG8957/Sculith/actions/runs/43751492841), 소스 `ed8bc8c`에서 통과했습니다.
**Windows GDK `1.26.63`에서 보고된 Terracotta 오류의 해결과 공식 게임 입장은 아직 확인되지 않았습니다.**

1. 기존 서버를 Ctrl+C로 종료합니다. 두 번 실행하면 포트 사용 중 오류가 납니다.
2. ZIP 전체를 새 폴더에 압축 해제합니다.
3. 기존 월드를 유지하려면 서버가 꺼진 상태에서 `sculith.toml`과 `world` 폴더 전체를 새 폴더로 복사합니다.
4. `diagnose.cmd`를 실행하고 같은 PC의 베드락에서 주소 `127.0.0.1`, 포트 `19132`로 접속합니다.

기존 로컬 세션 설정에서도 새 연결 경로가 자동 활성화됩니다. `nethernet = false`를 직접 지정했다면 비활성 상태를 유지합니다.
첫 접속에서 게임이 서버 신뢰 확인을 표시할 수 있습니다. 서명 키는 `world/nethernet-identity.pem`에 보관하고 재시작 시 유지합니다.
이 파일은 공유하지 마세요. 잘못된 기존 키는 덮어쓰지 않고 시작 오류로 알려줍니다.

진단 로그의 `NetherNet signaling request received`, `NetherNet WebRTC transport connected`와 베드락 로그인 실패 단계로 진행 위치를 구분할 수 있습니다.
NetherNet은 현재 같은 PC의 loopback 전용이며, TCP 19132와 임시 UDP 포트도 사용합니다.
설치기는 방화벽이나 관리자 설정을 자동 변경하지 않습니다.

기존 설정·월드를 덮어쓰지 않는 런처, 체크섬, 릴리스 메타데이터와 의존성 라이선스가 포함됩니다.
Java 월드 입장, 완전한 멀티플레이·인벤토리·생존과 리소스팩 호환성은 아직 미구현입니다.

English: Adds bounded local NetherNet HTTP signaling/WebRTC, persistent signed server identity, real-socket transport tests and shared RakNet/NetherNet world deltas. Official game-client entry and the reported Terracotta failure remain unverified. Preserve settings and the entire world directory, stop the previous server, extract the ZIP and run `diagnose.cmd`. This is a development preview, not a complete crossplay server.
