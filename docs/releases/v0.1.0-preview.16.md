# Shared held-item preview

상대 플레이어가 손에 든 시작 아이템과 슬롯 변경을 양쪽에 표시합니다.
체크무늬 Stone·Dirt·Grass·빈 손을 같은 서버 상태에서 전달합니다.
기존 플레이어 표시·이동·퇴장과 팩·Rust 예제 4개를 유지합니다.

ZIP 전체를 새 폴더에 풀고 `start.cmd`로 실행합니다.

- 베드락: 같은 PC의 `127.0.0.1`, 포트 `19132`.
- 순정 Java **26.3**: `127.0.0.1:25565`.
- 필수 팩 사용에 동의하세요. 자세한 접속 로그는 `diagnose.cmd`를 사용합니다.
- 서버에 Rust·Python·Java 런타임이 필요하지 않습니다. 기존 설정·월드는 보존합니다.

## 변경과 범위

서버 소유자의 선택 슬롯에서 아이템을 가져옵니다. 클라이언트의 아이템·수량
주장은 슬롯 내용을 바꾸지 못하며, 잘못된 주장도 정해진 아이템으로 정정합니다.
늦게 접속하거나 로드 범위에 다시 들어온 플레이어도 현재 선택을 받습니다.
같은 슬롯의 반복 선택은 알림을 만들지 않습니다. 빈 슬롯은 손을 비웁니다.
개인 플러그인 효과·게임 훅·월드 리비전과 분리했습니다. API 버전은 **5**로 유지합니다.

수량은 기존 크리에이티브 시작 슬롯의 64개입니다. 일반 인벤토리·아이템 드롭/줍기·
갑옷·보조 손·내구도·계정 스킨·전투는 아직 구현하지 않았습니다.

## 검증

정확한 소스 `5eba35cb0f9ca3843b2bfb6d71e7796433b3ca1a`의 실제 순정 Linux Java 게임에서
양쪽 손의 같은 원본 체크무늬 블록, 실제 숫자 키로 고른 Dirt, 양쪽 빈 손 전환과 퇴장을 확인했습니다.
별도 Go/Pion 베드락 구현에서도 실제 Java 슬롯 변경을 수신했습니다.
독립 Python/Go 검사는 양방향 선택, 거짓 아이템·수량 정정, 늦은 입장과 빈 손을 검사합니다.
