# Bedrock loading sequence preview

Preview 5의 공식 Windows GDK 1.26.63 재접속은 로그인에 성공했지만 로딩 중 Boat / InitialConnection-148, spawn-acknowledgement에서 실패했습니다.
프로토콜 2225의 오류 148은 MissingStructureData입니다. 누락됐던 JigsawStructureData의 네 빈 레지스트리를 StartGame 전에 전송하도록 수정합니다.

- 독립 클라이언트도 구조 데이터가 StartGame 전에 도착하는지 검사합니다.
- 초기화 확인 전에 도착하는 지연 확인·이모트 목록·로딩 진단 메시지를 처리합니다. 게임 입력은 초기화 전에는 월드를 변경하지 않습니다.
- 로딩 중과 입장 후의 청크 반경 재요청을 처리합니다. 같은 반경 요청에 청크 전체나 스폰을 중복 전송하지 않습니다.
- 청크가 사용하는 평원 바이옴 정의와 빈 크리에이티브 목록을 전송합니다. 일반 인벤토리/제작 기능은 아직 구현 중입니다.
- 예상하지 못한 패킷 번호, 잘못된 초기화 엔티티 번호, 클라이언트가 보고한 패킷 위반 종류를 로그에 표시합니다. 로그인 토큰과 진단 문자열 원문은 기록하지 않습니다.
- 별도 개발용 클라이언트에서 Dragonfly의 청크 디코더와 전체 블록 레지스트리로 25청크의 2,457,600개 블록과 바이옴을 검증합니다. Go 코드나 해당 레지스트리는 배포 구동기에 포함되지 않습니다.

코드 148의 정의는 고정된 [bedrock-rs 5221fcae](https://github.com/bedrock-crustaceans/bedrock-rs/blob/5221fcae8cc8468f523f3f58f129cb308e9d3369/crates/protocol/src/version/v2225/enums/connection_fail_reason.rs)에 있습니다.
전송 순서는 [gophertunnel e2251a60](https://github.com/Sandertv/gophertunnel/blob/e2251a60f71d5faa9784d6a4bc817c117cb6af78/minecraft/conn.go)의 startGame과 대조했습니다.
공식 게임에서 이 수정 후 월드에 들어가는지는 재접속 검증이 필요합니다.

기존 서버를 Ctrl+C로 종료하고 ZIP 전체를 새 폴더에 푼 뒤 diagnose.cmd를 실행하세요. 주소는 127.0.0.1, 포트는 19132입니다. 기존 데이터를 이어 쓰려면 종료 상태에서 sculith.toml과 world 폴더 전체를 복사하세요.
