# NetherNet DTLS login preview

Preview 4가 실제 Windows GDK 클라이언트에서 WebRTC 연결과 프로토콜 2225 협상까지 진행한 뒤 InitialConnection-66, encryption-handshake에서 실패한 문제를 수정합니다.

NetherNet은 이미 DTLS로 암호화된 전송이므로 RakNet용 추가 암호화 핸드셰이크를 보내지 않습니다. 로그인 서명과 인증 정책은 계속 검사하며, 로그인 키가 SDP 서명으로 증명한 키와 일치해야 합니다. RakNet의 패킷 암호화는 유지합니다.

- 독립 aiortc/OpenSSL 클라이언트로 전송·서버 서명·DTLS 기반 로그인과 팩 협상 시작을 검증합니다.
- 별도의 gophertunnel/Go/Pion 클라이언트로 로그인·팩 협상·월드 스폰·서버의 플레이어 활성화를 확인합니다. 이 개발용 클라이언트나 Go/Python 런타임은 설치한 구동기에 필요하지 않습니다.
- 비신뢰 채널의 이동 입력도 기존 서버 권위 검증으로 처리합니다. 유효한 이동과 잘못된 순간이동의 교정, 다른 키의 로그인 거부를 테스트합니다.
- 인증 공개키 조회는 운영체제의 신뢰 저장소로 HTTPS를 검증합니다. 평문 HTTP와 신뢰되지 않은 인증서는 거부합니다. 실제 온라인 계정 로그인은 아직 검증 중입니다.
- 실패 로그에 토큰 원문 없이 원인 분류를 표시합니다.

기존 서버를 Ctrl+C로 종료하고 ZIP 전체를 새 폴더에 푼 뒤 diagnose.cmd를 실행하세요. 주소는 127.0.0.1, 포트는 19132입니다.
기존 데이터를 유지하려면 종료 상태에서 sculith.toml과 world 폴더 전체를 복사하세요. 운영자 서명 키를 보존하며 외부에 공유하지 마세요.

공식 Minecraft의 월드 입장·렌더링 성공은 아직 미확인입니다. Java 월드 입장과 전체 게임/팩 호환성도 구현 중입니다.

English: Uses NetherNet's existing DTLS protection without requesting the RakNet application-cipher handshake, binds Bedrock login to the signed SDP key, validates unreliable movement and adds independent full login/spawn tests. OS-verified HTTPS authentication metadata initialization is corrected. Official Minecraft gameplay remains awaiting a retest.
