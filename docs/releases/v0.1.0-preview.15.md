# Shared player visibility preview

같은 월드에 접속한 자바·베드락 플레이어의 이름, 아바타와 이동을 서로 표시합니다.
나중에 들어온 플레이어도 현재 위치를 받고, 퇴장하면 화면과 접속자 목록에서 제거합니다.
기존 팩·Rust 게임/메뉴/사운드/모델 예제 4개를 유지합니다.

ZIP 전체를 새 폴더에 풀고 `start.cmd`로 실행하세요.

- 베드락: 같은 PC의 `127.0.0.1`, 포트 `19132`.
- 순정 Java **26.3**: `127.0.0.1:25565`.
- 필수 팩 사용에 동의해야 합니다. `diagnose.cmd`는 자세한 접속 로그를 남깁니다.
- 기존 설정과 월드는 보존합니다. Rust·Python·Java 런타임은 서버에 필요 없습니다.

## 변경

단일 월드 소유자가 초기화된 접속자와 이동을 결정합니다. 스냅샷과 이후 알림을
한 지점에서 연결해 늦은 접속·퇴장 시 표시가 어긋나지 않도록 했습니다.
화면에 로드한 청크 안의 상대만 생성하며, 범위를 벗어나도 접속자 목록은 유지합니다.
큐는 128개, 상대는 최대 63명으로 제한합니다. 누락된 알림이 있으면 재접속이 필요합니다.
개인 플러그인 메시지·메뉴·사운드·장식 모델은 이 공개 스트림에 섞이지 않습니다.

Java는 순정 기본 스킨, 베드락은 직접 만든 초록색 임시 스킨/기하를 사용합니다.
원래 계정 스킨·망토·페르소나·장비·팔 동작·전투·플레이어 충돌은 아직 구현하지 않았습니다.
한글·이모지 이름은 Java 프로필 이름 규칙에 맞는 대체 이름과 원래 표시 이름으로 전달합니다.
빈 손의 불필요한 추가 데이터를 없애 독립 베드락 구현의 생성 패킷 읽기 실패도 수정했습니다.
Rust 플러그인 API 버전은 **5**로 유지합니다.

## 검증

정확한 소스 `44a6a681cfade5a2e6aa2a183f788ac4e5980920`에서 모드 없는 실제 Linux Java 게임으로
상대 아바타·접속자 목록·이동 키 입력·상대 퇴장을 확인했습니다.
실제 Java 이동을 독립 Go/Pion 베드락 클라이언트에서도 수신했습니다.
독립 Python/Go 검사는 양방향 이동, 늦은 입장의 최신 위치, 이름과 퇴장 순서를 확인합니다.
Linux Clippy, 프로젝트 테스트 134개, 소유권 doctest, vendor 테스트 256개와
기존 접속·블록·플러그인·메뉴·사운드·모델·필수 팩/캐시 검사가 통과했습니다.

네이티브 Windows [run 43816295927](https://github.com/SKYRPG8957/Sculith/actions/runs/43816295927)에서도
새 플레이어 검사와 기존 실행·접속·팩·예제·압축본·실행기 검사가 통과했습니다.
압축본은 **6,591,847 bytes**, SHA-256
`b3e53d511f6613f52c1e2df5492ac9e3b974e4151e3f0b3eec02199d751c7175`.
24개 파일, 다섯 EXE의 시스템 DLL 구성, 소스 메타데이터와 라이선스를 검사했습니다.
[공개 배포 run 43817319113](https://github.com/SKYRPG8957/Sculith/actions/runs/43817319113) 이후
인증 없는 HTTPS로 ZIP과 체크섬을 새로 받아 소스·태그·SHA-256을 재검증했습니다.
설치기와 다운로드 기본값은 Preview 15입니다. Windows 공개 설치 검증은 진행 중입니다.
ZIP README의 ‘다른 플레이어 표시 미완료’는 이전 설명입니다. 이 버전에는 위의 기본 표시 기능이 포함됩니다.

**공식 Windows 베드락 게임의 실제 입장은 이 환경에서 확인하지 못했습니다.**
베드락 검증은 독립 프로토콜 클라이언트 결과이며, 순정 Java 실제 게임 검증과 구분합니다.
로컬 개발용 프리뷰입니다. 공개 온라인 인증/호스팅과 전체 게임·콘텐츠 호환은 아직 지원하지 않습니다.
